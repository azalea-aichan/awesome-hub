# AWESOME HUB

A shortcut hub for local apps, external websites, and hosted static sites. Node.js 18+ is required.

    node server.js          # http://0.0.0.0:8080
    PORT=9000 node server.js
    HOST=0.0.0.0 node server.js   # agar bisa diakses dari HP / perangkat lain

- App data is stored in `data/apps.json`; uploaded logos are stored in `data/uploads/`.
- Link and port cards automatically use the destination's `/favicon.ico` when no custom logo is set; if it is unavailable, the card displays the first letter of its title. Enable "Keep current favicon when address changes" to preserve the current favicon when editing a card's address.
- Upload an `.html` or `.htm` file from a card's edit form to host it at `/pages/...` on this server; its card opens the hosted page without starting a separate app server. HTML pages run in an isolated sandbox, separate from the hub's origin, with outbound resource loading blocked.
- Deleting a card removes its uploaded HTML, ZIP site, or logo when no other card still uses that asset.
- Upload a ZIP static site from a card's edit form; the archive must contain `index.html` at its root or within a `public/` folder, including inside a project wrapper folder. The root `index.html` takes priority; otherwise the matching `public/` folder becomes the served site root. Each ZIP site gets its own port/origin, allowing browser storage and downloads without sharing the hub's origin. Port assignments are saved in `data/site-ports.json` and restored at startup. Make sure the server firewall and network allow those dynamically assigned ports; a reverse proxy must expose them too. The site listener uses HTTP, so secure-context-only browser features still depend on the browser environment. Root-relative asset paths in HTML and CSS are adjusted to the hosted site URL. `node_modules` folders are skipped during extraction. ZIP files are limited to 100 MB, extracted sites to 150 MB and 1000 entries. Uploaded sites cannot run server-side code. Network requests are blocked by default. To call an API without browser CORS when its port changes between projects, set `SITE_API_PROXY_HOST` on the Awesome Hub server to its HTTP(S) scheme and hostname only, without a port (for example: `SITE_API_PROXY_HOST=http://ninehermes.gorgon-iwato.ts.net`). Restart/redeploy the server. Absolute URLs to that hostname with any port in hosted HTML, JavaScript, and JSON files are rewritten to a same-origin proxy; only the configured hostname and scheme are allowed, while the port is taken from each API URL. The startup log reports whether the dynamic-port proxy is enabled. Cookies and browser origin headers are not forwarded. Keep API keys out of this setting; keys included by the app are still visible to users of the site. `SITE_API_PROXY_ORIGIN` remains supported for a fixed API origin. `SITE_CONNECT_SRC` remains available for direct API calls, but the API must allow the hosted site's origin through CORS.
- **ZIP Node app (card type).** Upload a project that has a backend (`server.js`, or `main` in `package.json`, `index.js`, `app.js`). The hub extracts it to `data/apps/<id>/`, runs `npm install --omit=dev` when `package.json` lists dependencies, and starts it with `node` as a child process, passing `PORT` (assigned by the hub) and `HOST=0.0.0.0`. A project that only has `index.html` plus browser scripts is rejected (use *ZIP static site* for it); `index.js`/`app.js` that use `document`/`window`/`addEventListener` and no Node APIs are never run as a server. The app must listen on `process.env.PORT`. The card opens `http://<hub host>:<app port>/`, so the frontend and its `/api/*` are served by the app itself (no CSP, no proxy). Per-card *Environment variables* (`KEY=VALUE` per line) are stored only in `data/app-env.json` (mode 600), never in `apps.json` or in API responses; every non-empty, non-`#` line must be `NAME=value` (a bare value, an invalid name, or `PORT`/`HOST` is rejected with the line number); saved values appear as `********` in the form and are kept unless you edit that line. Changing them restarts the app. Apps are restarted when the hub starts, stopped when it stops, and re-started when a crashed app's card is opened. Deleting the card (or replacing its ZIP) stops the process and deletes its folder, port record and environment variables. Folders no card points to are removed on startup. Output is written to the hub's log (`journalctl -u awesome-hub`, lines prefixed `[app <id>]`). Only upload projects you trust: the code runs on this server with the hub's permissions. Node.js only; for sites without a backend use *ZIP static site*.
- **Unsaved uploads.** The add/edit form closes only with *Cancel* or *Save* (clicking outside or pressing Esc does nothing). Whatever you upload in the form (HTML page, ZIP, Node app, logo) is removed again when you press *Cancel*, upload a replacement, or change the card type; the card's previously saved project is never touched until you press *Save*. `POST /api/discard-upload` does the removal and refuses anything a saved card uses.
- **Favicons for hosted cards.** Like link cards, HTML page, ZIP static site and ZIP Node app cards show the project's own icon when it has one (the *Logo* field still wins). `GET /api/favicon?target=<card target>` looks for `<link rel="icon">` / `shortcut icon`, then `apple-touch-icon`, in the page or the project's `index.html` (inline `data:` URIs, files inside the project, or an absolute URL), then for `favicon.ico/.png/.svg`, `apple-touch-icon.png`, `icon.png/.svg`. For a Node app it checks `public/`, `static/`, `dist/`, `build/`, `www/` and the project root, and, if the app is running, asks the app itself (`/` and `/favicon.ico`). Nothing is stored; files are limited to 1 MB; when nothing is found the usual first-letter badge is shown.
- **API hosts (per card).** In a ZIP/HTML card's edit form, fill *API hosts* with the hostnames the project calls (e.g. `ninehermes.gorgon-iwato.ts.net`, any port). The hub then serves the project with `connect-src 'self'`, rewrites absolute URLs of those hosts (static strings and, at runtime, `fetch`/`XMLHttpRequest`) to its own proxy, and forwards them server-side, so CORS is not needed. Only the listed hosts are reachable; no environment variable is required. `SITE_API_PROXY_HOST` / `SITE_API_PROXY_ORIGIN` / `SITE_CONNECT_SRC` still work.
- A numeric address is treated as a port on the same host as the hub.
- PWA installation and offline support require HTTPS or `localhost`. Installation is unavailable over plain HTTP on a LAN IP.
- There is no login. Do not expose this service to the internet without an authentication layer (such as Cloudflare Access or Tailscale).
